## 0. 이번에 새로 확인한 사실 (중요)

## 2. 1단계: 인증키 발급 (팀원 B, 약 10분)

1. https://open.assembly.go.kr 접속
2. 오른쪽 위 **회원가입** 후 로그인
3. 상단 메뉴 **Open API** 클릭 (주소: https://open.assembly.go.kr/portal/openapi/main.do)
4. **인증키 발급** 메뉴 클릭 (주소: https://open.assembly.go.kr/portal/openapi/openApiActKeyIssPage.do)
5. 사용 목적 칸에 예시처럼 입력: `국회 법안 정보를 쉽게 요약해 전달하는 팀프로젝트 웹서비스 개발`
6. 발급된 키는 **인증키 발급내역** 메뉴에서 다시 볼 수 있다

※ 3~6번의 메뉴 위치는 2026-11-26 사이트 메뉴 목록으로 확인했다. 로그인 후 실제 신청 화면은 확인하지 못했으므로 화면 문구가 조금 다를 수 있다.

※ 공공데이터포털(data.go.kr)에서 "활용신청"을 해도 되지만, 이 API는 결국 열린국회정보 키로 호출하므로 열린국회정보에서 바로 받는 것이 빠르다.

## 3. 2단계: 인증키를 안전하게 넣기

1. 프로젝트 폴더의 `.env.example` 파일을 복사해서 이름을 `.env` 로 바꾼다
2. 메모장으로 `.env`를 열고 `ASSEMBLY_API_KEY=` 뒤에 키를 붙여 넣고 저장한다
   (예: `ASSEMBLY_API_KEY=abcd1234...` 처럼 띄어쓰기 없이)
3. **절대 하지 말 것:** 키를 카톡, 채팅, 깃허브, 노션 등에 붙여 넣기. 클로드에게도 알려줄 필요 없다.

키 없이도 1~10건 조회는 되므로 이 단계를 건너뛰고 4단계를 먼저 해봐도 된다.

## 4. 3단계: 실제 법안 조회하기

PowerShell(윈도우 검색창에 "PowerShell")을 열고, 프로젝트 폴더로 이동한 뒤 실행한다.

처음 한 번만 (엑셀 파일 만들기용 도구 설치):

```powershell
pip install openpyxl
```

법안 조회:

```powershell
python fetch_bill.py 2218220
```

여러 법안을 한 번에:

```powershell
python fetch_bill.py 2218220 2223257
```

정상이라면 이렇게 나온다:

```
호출 방식: 샘플 모드(인증키 없음)
[2218220] 개인정보 보호법 일부개정법률안 / 한창민의원 등 11인 / 법안소위 심사 중 (2026-08-26)
저장 완료: ...\output
```

키를 넣었다면 첫 줄이 `호출 방식: 인증키 사용` 으로 바뀐다.

## 5. 4단계: 결과 확인

`output/bills.xlsx`를 엑셀로 연다. 한 줄이 법안 하나다.

| 열 이름 | 뜻 | 어디서 오나 |
|---|---|---|
| bill_id | 의안번호 | API |
| bill_name | 법안 이름 | API |
| proposer | 대표발의자 | API |
| propose_date | 제안일 | API |
| committee | 소관위원회 | API |
| status | 현재 진행 상황 (자동 판단) | API 날짜 + 소위 날짜 |
| status_date | 그 단계의 날짜 | 위와 같음 |
| stage_no | 진행 단계 번호 (1 발의 ~ 9 공포, 0은 폐기/철회/부결로 진행 종료) | 자동 계산 |
| committee_referred_date | 위원회 회부일 | API |
| committee_present_date | 위원회 상정일 | API |
| subcommittee_name | 법안소위 이름 (비어 있는 경우 많음) | 소위 API (자동) |
| subcommittee_referred_date | 법안소위 회부일 | 소위 API (자동) |
| subcommittee_present_date | 법안소위 상정일 | 소위 API (자동) |
| subcommittee_proc_date | 법안소위 처리일 | 소위 API (자동) |
| subcommittee_result | 법안소위 처리결과 | 소위 API (자동) |
| proposal_reason | 제안이유 원문 | 제안이유 API (자동) |
| main_content | 주요내용 원문 (원문에 구분이 없는 법안은 proposal_reason에 전체가 들어감) | 제안이유 API (자동) |
| note | 참고사항 (다른 법안과 연결된 경우 등) | 제안이유 API (자동) |

| source_url | 데이터 출처 (열린국회정보) | 고정값 |
| last_checked | 조회한 날짜 | 실행 날짜 |
| api_status | API 호출 결과 | 실행 결과 |

### 오류가 날 때

| 화면 메시지 | 뜻 | 해결 |
|---|---|---|

| `ERROR-290` 등 키 관련 메시지 | 인증키가 틀림 | `.env`의 키 앞뒤 공백, 오타 확인 |

## 6. 5단계: 새 법안 추가하는 방법

`python fetch_bill.py 새의안번호` 실행 → 기본 정보, 제안이유, 주요내용, 법안소위 날짜가 **모두 자동으로** 들어온다.

API에서 못 가져온 경우에만 `data/bill_texts.json`에 직접 넣은 값을 대신 쓰고, 그것도 없으면 "미확인(원문 없음)"으로 표시된다.

## 6-1. 자동 업데이트

GitHub가 **2시간마다** 국회 API를 확인한다. **새 법안이 발의됐거나, 추적 중인 법안(`bills.txt`)의 상태가 바뀌었을 때만** `output` 폴더를 고쳐 저장소에 올린다. 바뀐 게 없으면 아무것도 올리지 않는다. 아무도 컴퓨터를 켜 둘 필요가 없다.

※ 국회 API는 "바뀌면 알려주는" 기능이 없어서, 바뀌었는지는 물어봐야만 알 수 있다. 그래서 2시간마다 묻되, 묻는 횟수를 최소로 줄였다.

**인증키 사용량 (한 번 확인할 때):**

| 항목 | API 호출 |
|---|---|
| 새 법안 확인 (최근 100건 한 번에) | 1회 |
| 진행 중인 법안 | 법안당 1회 (위원회 심사 중이면 소위 확인까지 2회) |
| 끝난 법안 (폐기, 철회, 부결) | 0회 |
| 제안이유 | 처음 추가할 때 1회만 |

지금(법안 2건)은 한 번에 5회, 하루 60회 정도다. 열린국회정보 API 명세에는 API마다 "요청제한횟수 200,000"으로 적혀 있다(기간 단위는 미확인). 호출 횟수는 실행할 때마다 `이번 실행의 API 호출: N회`로 표시된다. 더 줄이려면 워크플로 파일의 `cron` 값을 바꾸면 된다 (예: `"0 */6 * * *"`는 6시간마다).

| 하고 싶은 것 | 방법 |
|---|---|
| 추적할 법안 추가/삭제 | GitHub에서 `api-server/bills.txt`를 열고 연필 아이콘으로 수정, 의안번호를 한 줄에 하나씩 |
| 지금 바로 업데이트 | 저장소 **Actions** 탭 > **Update bills** > **Run workflow** |
| 잘 돌았는지 확인 | Actions 탭에서 초록 체크 표시. 실패하면 빨간 X |
| 진행 상황이 바뀐 법안 보기 | `output/changes.json` (최근 변경이 맨 위). 알림 기능에 그대로 사용 가능 |
| 새로 발의된 법안 보기 | `output/new_bills.json` (최근 발견이 맨 위, 최대 500건). 관심 있는 법안은 번호를 `bills.txt`에 추가하면 추적 시작 |

**인증키 등록 (한 번만, 저장소 관리자가):** 저장소 **Settings > Secrets and variables > Actions > New repository secret**, 이름 `ASSEMBLY_API_KEY`, 값에 인증키. 등록하지 않아도 샘플 모드로 동작하지만, 등록해 두는 것을 권장한다. 인증키는 이곳에만 넣고 파일에 적지 않는다.

조회에 실패한 법안은 이전 데이터를 그대로 두므로, 국회 서버가 잠깐 멈춰도 데이터가 사라지지 않는다.

## 7. 팀원에게 넘길 것

- **팀원 A (화면):** `output/bills.json` 또는 `bills.xlsx`. 진행 단계 표시는 `stage_no`(1~9)와 `status` 사용. 단계 이름 목록은 `fetch_bill.py`의 `STAGES`.
- **팀원 C (AI 요약):** `proposal_reason`, `main_content`, `original_url`. 요약과 숏폼 대본은 반드시 이 원문 기준으로 만들고, 영상에는 "2026-11-26 기준 법안소위 심사 중"처럼 확인 날짜를 함께 표기.
