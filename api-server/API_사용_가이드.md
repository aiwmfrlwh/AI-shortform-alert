# 국회 법안 API 사용 가이드 (AI즐기조)

작성일: 2026-11-26

## 0. 이번에 새로 확인한 사실 (중요)

| 항목 | 내용 | 확인 여부 |
|---|---|---|
| API 실제 위치 | 공공데이터포털(data.go.kr) 페이지는 **안내용 링크**이고, 실제 API와 인증키 발급은 **열린국회정보(open.assembly.go.kr)** 에서 한다. data.go.kr 페이지의 "API 유형: LINK", "데이터조회하기" 버튼이 열린국회정보로 연결됨 | 확인 |
| 인증키 없이 호출 | 인증키 없이도 "샘플 모드"로 최대 10건까지 조회된다 (열린국회정보 개발가이드에 명시) | 확인 |
| 실제 API 호출 | 2026-11-26, 인증키 없이 샘플 모드로 의안번호 2218220 조회 **성공** | 확인 |
| 법안 원문 대조 | 국회 의안정보시스템 상세 페이지의 "제안이유 및 주요내용" 원문 확인. 기존 요약 4가지(법정손해배상, 임시중지명령, 이행강제금, 영업정지 요청)가 원문과 **일치함** | 확인 |
| 진행 상황 변화 | 2026-08-26 위원회 전체회의에서 상정된 뒤 **같은 날 법안심사소위원회로 회부됨**. 현재(11-26) 소위 심사 중, 소위 처리일은 비어 있음 | 확인 |
| 인증키 발급 | 아직 안 함 (팀원 B가 직접 해야 함) | 미완료 |
| 제안이유 자동 수집 | 별도 공식 API **"법률안 제안이유 및 주요내용"(BPMBILLSUMMARY)** 로 자동 수집. 2026-11-26 법안 5건으로 테스트 성공, 수동으로 옮긴 원문과 글자까지 일치 | 확인 |

## 1. 폴더 안 파일 설명

| 파일 | 용도 |
|---|---|
| `fetch_bill.py` | 의안번호를 넣으면 API로 조회해서 엑셀/CSV/JSON을 만들어 주는 프로그램 |
| `data/bill_texts.json` | 법안소위 회부일 (API에 없는 정보) 수동 입력. 제안이유는 API가 실패할 때만 쓰는 예비용 |
| `.env.example` | 인증키 넣는 파일의 견본 |
| `.gitignore` | 깃허브에 올릴 때 인증키 파일(.env)이 올라가지 않게 막는 설정 |
| `output/bills.xlsx`, `bills.csv`, `bills.json` | 실행 결과 (팀원 A, C에게 전달할 파일) |
| `output/raw_2218220.json` | API가 보내준 원본 그대로 (증거 및 확인용) |

## 2. 1단계: 인증키 발급 (팀원 B, 약 10분)

1. https://open.assembly.go.kr 접속
2. 오른쪽 위 **회원가입** 후 로그인
3. 상단 메뉴 **Open API** 클릭 (주소: https://open.assembly.go.kr/portal/openapi/main.do)
4. **인증키 발급** 메뉴 클릭 (주소: https://open.assembly.go.kr/portal/openapi/openApiActKeyIssPage.do)
5. 사용 목적 칸에 예시처럼 입력: `국회 법안 정보를 쉽게 요약해 전달하는 팀프로젝트 웹서비스 개발`
6. 발급된 키는 **인증키 발급내역** 메뉴에서 다시 볼 수 있다

※ 3~6번의 메뉴 위치는 2026-11-26 사이트 메뉴 목록으로 확인했다. 로그인 후 실제 신청 화면은 확인하지 못했으므로 화면 문구가 조금 다를 수 있다.

※ 공공데이터포털(data.go.kr)에서 "활용신청"을 해도 되지만, 이 API는 결국 열린국회정보 키로 호출하므로 열린국회정보에서 바로 받는 것이 빠르다.

## 3. 2단계: 인증키를 안전하게 넣기

1. 프로젝트 폴더의 `.env.example` 파일을 복사해서 이름을 `.env` 로 바꾼다
2. 메모장으로 `.env`를 열고 `ASSEMBLY_API_KEY=` 뒤에 키를 붙여 넣고 저장한다
   (예: `ASSEMBLY_API_KEY=abcd1234...` 처럼 띄어쓰기 없이)
3. **절대 하지 말 것:** 키를 카톡, 채팅, 깃허브, 노션 등에 붙여 넣기. 클로드에게도 알려줄 필요 없다.

키 없이도 1~10건 조회는 되므로 이 단계를 건너뛰고 4단계를 먼저 해봐도 된다.

## 4. 3단계: 실제 법안 조회하기

PowerShell(윈도우 검색창에 "PowerShell")을 열고, 프로젝트 폴더로 이동한 뒤 실행한다.

처음 한 번만 (엑셀 파일 만들기용 도구 설치):

```powershell
pip install openpyxl
```

법안 조회:

```powershell
python fetch_bill.py 2218220
```

여러 법안을 한 번에:

```powershell
python fetch_bill.py 2218220 2223257
```

정상이라면 이렇게 나온다:

```
호출 방식: 샘플 모드(인증키 없음)
[2218220] 개인정보 보호법 일부개정법률안 / 한창민의원 등 11인 / 법안소위 심사 중 (2026-08-26)
저장 완료: ...\output
```

키를 넣었다면 첫 줄이 `호출 방식: 인증키 사용` 으로 바뀐다.

## 5. 4단계: 결과 확인

`output/bills.xlsx`를 엑셀로 연다. 한 줄이 법안 하나다.

| 열 이름 | 뜻 | 어디서 오나 |
|---|---|---|
| bill_id | 의안번호 | API |
| bill_name | 법안 이름 | API |
| proposer | 대표발의자 | API |
| propose_date | 제안일 | API |
| committee | 소관위원회 | API |
| status | 현재 진행 상황 (자동 판단) | API 날짜 + 소위 회부일 |
| status_date | 그 단계의 날짜 | 위와 같음 |
| stage_no | 진행 단계 번호 (1 발의 ~ 9 공포) | 자동 계산 |
| committee_referred_date | 위원회 회부일 | API |
| committee_present_date | 위원회 상정일 | API |
| subcommittee_referred_date | 법안소위 회부일 | 의안정보시스템 (수동 입력) |
| proposal_reason | 제안이유 원문 | 제안이유 API (자동) |
| main_content | 주요내용 원문 (원문에 구분이 없는 법안은 proposal_reason에 전체가 들어감) | 제안이유 API (자동) |
| note | 참고사항 (다른 법안과 연결된 경우 등) | 제안이유 API (자동) |
| text_source | 원문을 어디서 가져왔는지 (API 자동 / 수동 입력 / 없음) | 자동 표시 |
| original_url | 법안 공식 상세 페이지 주소 | API |
| source_url | 데이터 출처 (열린국회정보) | 고정값 |
| last_checked | 조회한 날짜 | 실행 날짜 |
| api_status | API 호출 결과 | 실행 결과 |

### 오류가 날 때

| 화면 메시지 | 뜻 | 해결 |
|---|---|---|
| `INFO-200 해당하는 데이터가 없습니다` | 그 의안번호가 없음 | 번호 확인. 제22대 국회 법안만 조회됨 |
| `ERROR-290` 등 키 관련 메시지 | 인증키가 틀림 | `.env`의 키 앞뒤 공백, 오타 확인 |
| `연결 실패` | 인터넷 또는 국회 서버 문제 | 잠시 후 다시 실행 |
| `python`을 찾을 수 없음 | 파이썬 미설치 | python.org 에서 설치 (설치 시 "Add to PATH" 체크) |

## 6. 5단계: 새 법안 추가하는 방법

1. `python fetch_bill.py 새의안번호` 실행 → 기본 정보와 제안이유, 주요내용이 **모두 자동으로** 들어온다
2. (선택) 법안소위 단계까지 표시하려면: 엑셀의 `original_url` 주소를 열어 "소위 심사정보"의 회부일을 확인하고, `data/bill_texts.json`에 `"subcommittee_referred_date"`로 추가

API에서 원문을 못 가져오면 `data/bill_texts.json`에 직접 넣은 원문을 대신 쓰고, 그것도 없으면 "미확인(원문 없음)"으로 표시된다.

## 7. 팀원에게 넘길 것

- **팀원 A (화면):** `output/bills.json` 또는 `bills.xlsx`. 진행 단계 표시는 `stage_no`(1~9)와 `status` 사용. 단계 이름 목록은 `fetch_bill.py`의 `STAGES`.
- **팀원 C (AI 요약):** `proposal_reason`, `main_content`, `original_url`. 요약과 숏폼 대본은 반드시 이 원문 기준으로 만들고, 영상에는 "2026-11-26 기준 법안소위 심사 중"처럼 확인 날짜를 함께 표기.
